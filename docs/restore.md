# Восстановление AS-CORE

Этот документ описывает ручное восстановление схемы и Edge Function. Не выполняйте восстановление поверх существующей рабочей базы без резервной копии.

## Перед восстановлением

1. Создать новый Supabase project в допустимом регионе и с учётом требований к персональным данным.
2. Проверить тариф, регион, резервное копирование и лимиты.
3. Открыть SQL Editor нового проекта.
4. Проверить `supabase/schema_snapshot.sql` и выполнить его только на пустой тестовой базе.
5. Сверить таблицы, ограничения, индексы, RLS и политики с исходным снимком.

## Секреты Edge Function

Значения не хранятся в GitHub. Настроить в Supabase Secrets вручную:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_WEBHOOK_SECRET`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY` (или предусмотренный текущим кодом `SUPABASE_SECRET_KEYS`)

Никогда не передавать эти значения в чат, README, коммиты или клиентское приложение.

## Развёртывание

1. Развернуть `supabase/functions/as-telegram-bot/index.ts` как Edge Function с именем `as-telegram-bot`.
2. Оставить JWT verification выключенным только потому, что входящий webhook аутентифицируется заголовком Telegram `x-telegram-bot-api-secret-token`; проверить эту защиту перед публикацией.
3. Установить webhook на новый URL только после проверки функции на тестовом боте.
4. Отправить `/start`, проверить меню и каждый callback.
5. Сверить Telegram webhook info и логи функции.

## Ограничения

- Этот snapshot не переносит клиентские данные, auth-пользователей, storage, project secrets, настройки доменов и исходные журналы.
- Текущий код бота остаётся информационным прототипом; полноценная CRM, запись и бонусная логика не реализованы.
- Не использовать текущую базу в регионе Frankfurt для хранения персональных данных клиентов РФ без отдельной правовой проверки.
